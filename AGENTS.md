# Product guardrail

Before implementing a proposed feature, assess it against mySwamp's core purpose and product language. Explicitly warn the user and give reasoned pushback when a feature would add friction to the one-frog experience, turn mySwamp into a generic task manager, weaken its calm/minimal character, confuse the frog/tadpole/water model, or damage the quality of data needed for future Deep Swamp analysis. Recommend the narrowest aligned alternative instead of silently implementing a conflicting request.
